# Add-ons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers and reviewers run on Sonnet.

**Goal:** Customers buy Local SEO and Performance marketing as monthly Razorpay subscriptions and a Press release as a
one-time payment from the dashboard's Add-ons page, pause, cancel, resume and keep subscriptions there, and every add-on
payment gets a GST tax invoice. Staff see add-ons on the client page, get new purchases in Journey's "Need you", set a
press release's status, and pause or cancel on a customer's behalf.

**Architecture:** The catalogue and the pure rules (price at purchase, what each state shows, what each button does)
live in `@firstfold/shared/lib/billing`. Each monthly purchase is its own Razorpay subscription on a Razorpay plan for
its exact amount, recorded in a new `add_on_subscriptions` table (the main plan's `subscriptions` table allows one live
row per business and drives website access, so it is not reused). Add-on payments are ordinary `payments` rows of a new
kind `add_on`, linked through a small `add_on_payments` table (a column on `payments` would make the schema files import
each other). Cancel and Pause call Razorpay's cancel at cycle end at once; Resume, Pay now and Keep it open a new
subscription through checkout. The Razorpay webhook looks an id up in the add-on table before the main plan's. A press
release is a `charges` row of a new kind `press_release`, paid through the existing charges path, with a
`press_releases` row for its status.

**Tech Stack:** TypeScript, Next.js 16 server actions and pages, Drizzle on PostgreSQL 16 with row-level security,
Vitest, Razorpay subscriptions and orders, pdf-lib invoices from the GST work.

**Spec:** `docs/superpowers/specs/2026-10-09-add-ons-design.md` (decisions confirmed by the owner 2026-10-09).

**Depends on:** the GST tax invoices plan (`2026-10-09-gst-tax-invoices.md`) being fully done and committed. Do not start
until the GST session has handed over (see Coordination).

**Commands:** unit tests `pnpm --filter <pkg> exec vitest run <file>`; integration files one at a time
`pnpm --filter @firstfold/<db|shared> exec vitest run --config vitest.integration.config.ts <file>`; all checks
`pnpm lint && pnpm typecheck && pnpm test && pnpm build`.

## Decisions (from the spec, plus engineering choices)

| # | Decision |
|---|---|
| A1 | Local SEO and Performance marketing are monthly; Press release is one-time. Every account can buy. One active subscription per add-on per business; press releases unlimited. |
| A2 | Price fixed at purchase: list price, Premium 10% off when the business is a Premium member then, 18% GST. Stored on the row; later catalogue or membership changes never touch it. |
| A3 | Each monthly purchase renews on its own purchase date, as its own Razorpay subscription. |
| A4 | Cancel and Pause both call Razorpay cancel at cycle end at once, and record `end_kind` cancel or pause. Nobody who cancelled can be charged again. No scheduled job. |
| A5 | Resume (from paused) and Pay now (payment failed, inside 7 days) open a new subscription, charged now, new month from today. Keep it opens a new subscription that starts on the old billing date (Razorpay `start_at`). The new row links to the one it continues (`continues_id`). |
| A6 | After Razorpay's 3 retries a subscription halts; the add-on shows "Payment failed" with Pay now for 7 days (`ADD_ON_GRACE_DAYS`), worked out from `halted_at` when shown. A charge that still arrives on that halted subscription is accepted and the add-on runs again. |
| A7 | Add-on payments are `payments` rows of kind `add_on`, linked by `add_on_payments`. They never use the plan kinds, so the plan's payment method, first payment and review checks ignore them. |
| A8 | Every add-on payment is invoiced through `issueTaxInvoiceSafely` with a new `add_on` source: the add-on's name, "Monthly subscription" and the period, the list price, the Premium discount as a discount with the note "Premium member, 10% off". A press release is a charge and is invoiced by the existing charge source. |
| A9 | No coupons, no affiliate earnings, no refunds in the app, no intake form. Ad platform costs are the customer's. |
| A10 | Staff pause or cancel with the same next-billing-date rule, recorded with the staff member. New purchases (and resumes) appear in Journey's "Need you" until marked contacted; a press release appears until its status leaves "We'll contact you". No new dock item (the dock is full). |
| A11 | Purchase details open in a native `<dialog>` (the `image-cropper.tsx` pattern). Pause and Cancel confirm inline ("Yes, cancel" / "Keep"), never in a modal (`DESIGN.md`). |
| A12 | Closing an account ends add-ons at the end of their paid period (incomplete or not-yet-started ones are cancelled at once). Erasure waits while an add-on is live. Add-on rows are kept on erasure as financial records. |

```ts
import { chargedAmountCents, GST_BASIS_POINTS } from "@firstfold/billing/tax";

/**
 * The digital-marketing services a business buys from the Add-ons page (docs/superpowers/specs/2026-10-09-add-ons-
 * design.md), and what each costs. Prices are net of GST, in paise, and match the website's Digital marketing page
 * (firstfold-website content/for-business.ts): change both together. A price here only affects new purchases; what a
 * business pays for an existing subscription is stored on it. Pure and browser-safe.
 */

export const ADD_ONS_PATH = "/add-ons";

/** What a Premium member takes off an add-on, as a whole percent, at the moment of purchase. */
export const PREMIUM_ADD_ON_DISCOUNT_PERCENT = 10;

/** Days after Razorpay gives up on a renewal during which the customer can still Pay now. */
export const ADD_ON_GRACE_DAYS = 7;

const PAISE_PER_RUPEE = 100;

export type AddOnId = "local-seo" | "performance-marketing" | "press-release";
export type MonthlyAddOnId = Extract<AddOnId, "local-seo" | "performance-marketing">;

export interface AddOn {
  readonly id: AddOnId;
  readonly title: string;
  /** One line on what the service does for the business. */
  readonly line: string;
  readonly billing: "monthly" | "one-time";
  /** The list price before any discount, net of GST, in paise. */
  readonly paise: number;
  /** What the price is for: "a month" or "a release". */
  readonly unit: string;
  /** Costs the ad platforms charge on top, said in a few words; absent when there are none. */
  readonly extra?: string;
  readonly platforms?: readonly string[];
}

/** The services, dearest first. */
export const ADD_ONS: readonly AddOn[] = [
  {
    id: "local-seo",
    title: "Local SEO",
    line: "Be found when people nearby search.",
    billing: "monthly",
    paise: 10_000 * PAISE_PER_RUPEE,
    unit: "a month",
  },
  {
    id: "performance-marketing",
    title: "Performance marketing",
    line: "Campaigns built to drive leads, enquiries, bookings, and sales.",
    billing: "monthly",
    paise: 8_000 * PAISE_PER_RUPEE,
    unit: "a month",
    extra: "+ platform fees",
    platforms: ["Facebook Ads", "Instagram Ads", "YouTube Ads", "Google Ads", "Google Business Profile"],
  },
  {
    id: "press-release",
    title: "Press release",
    line: "Your launch, offer or news, sent out.",
    billing: "one-time",
    paise: 7_000 * PAISE_PER_RUPEE,
    unit: "a release",
  },
];

export const MONTHLY_ADD_ON_IDS: readonly MonthlyAddOnId[] = ["local-seo", "performance-marketing"];

const BY_ID: ReadonlyMap<string, AddOn> = new Map(ADD_ONS.map((addOn) => [addOn.id, addOn]));

export function isAddOnId(value: string): value is AddOnId {
  return BY_ID.has(value);
}

export function isMonthlyAddOnId(value: string): value is MonthlyAddOnId {
  return (MONTHLY_ADD_ON_IDS as readonly string[]).includes(value);
}

export function addOnById(id: AddOnId): AddOn {
  const addOn = BY_ID.get(id);
  if (addOn === undefined) throw new Error(`Unknown add-on ${id}`);
  return addOn;
}

/** What one purchase costs, worked out once and stored on it. All amounts in paise. */
export interface AddOnPrice {
  readonly listCents: number;
  readonly discountCents: number;
  /** List less discount: the taxable value. */
  readonly netCents: number;
  readonly taxRateBasisPoints: number;
  /** What Razorpay takes: net plus GST, from chargedAmountCents like every other price. */
  readonly chargedCents: number;
}

export function addOnPrice(addOn: AddOn, premium: boolean): AddOnPrice {
  const discountCents = premium ? Math.round((addOn.paise * PREMIUM_ADD_ON_DISCOUNT_PERCENT) / 100) : 0;
  return {
    listCents: addOn.paise,
    discountCents,
    netCents: addOn.paise - discountCents,
    taxRateBasisPoints: GST_BASIS_POINTS,
    chargedCents: chargedAmountCents(addOn.paise, discountCents, GST_BASIS_POINTS),
  };
}
```

```ts
import { ADD_ON_GRACE_DAYS } from "./add-ons";

/**
 * What an add-on subscription shows and allows (docs/superpowers/specs/2026-10-09-add-ons-design.md, "Add-ons page").
 * Worked out from the stored row and the clock, so a scheduled end and the 7-day grace need no job. Pure and
 * browser-safe.
 */

export type AddOnSubscriptionStatus = "incomplete" | "scheduled" | "active" | "past_due" | "halted" | "cancelled";
export type AddOnEndKind = "cancel" | "pause";

/** The fields of an add_on_subscriptions row these rules read. */
export interface AddOnFacts {
  readonly status: AddOnSubscriptionStatus;
  readonly endKind: AddOnEndKind | null;
  /** The end of the paid period: the next billing date. Null before the first payment. */
  readonly currentPeriodEnd: Date | null;
  readonly haltedAt: Date | null;
  readonly endedAt: Date | null;
  /** For a kept subscription, the day it starts and is first charged. */
  readonly startAt: Date | null;
}

export type AddOnView =
  | { readonly state: "none" }
  | { readonly state: "active"; readonly renewsOn: Date }
  | { readonly state: "ending"; readonly endsOn: Date }
  | { readonly state: "pausing"; readonly pausesOn: Date }
  | { readonly state: "paused"; readonly since: Date }
  | { readonly state: "failing" }
  | { readonly state: "failed"; readonly payBy: Date }
  | { readonly state: "ended" };

export type AddOnAction = "buy" | "pause" | "cancel" | "keep" | "resume" | "pay-now";

const DAY_MS = 24 * 60 * 60 * 1000;

function periodEnd(facts: AddOnFacts): Date {
  if (facts.currentPeriodEnd === null) throw new RangeError("A paid add-on has no period end");
  return facts.currentPeriodEnd;
}

/**
 * `current` is the business's newest add-on row for one add-on that is not an unpaid checkout; `successor` is a kept
 * subscription waiting to start (status scheduled), or null.
 */
export function addOnView(current: AddOnFacts | null, successor: AddOnFacts | null, now: Date): AddOnView {
  if (successor !== null && successor.status === "scheduled" && successor.startAt !== null) {
    return { state: "active", renewsOn: successor.startAt };
  }
  if (current === null) return { state: "none" };
  switch (current.status) {
    case "incomplete":
      return { state: "none" };
    case "scheduled":
      if (current.startAt === null) throw new RangeError("A scheduled add-on has no start");
      return { state: "active", renewsOn: current.startAt };
    case "active": {
      const end = periodEnd(current);
      if (current.endKind === null) return { state: "active", renewsOn: end };
      if (end.getTime() > now.getTime()) {
        return current.endKind === "cancel" ? { state: "ending", endsOn: end } : { state: "pausing", pausesOn: end };
      }
      return current.endKind === "cancel" ? { state: "ended" } : { state: "paused", since: end };
    }
    case "past_due":
      return { state: "failing" };
    case "halted": {
      if (current.haltedAt === null) throw new RangeError("A halted add-on has no halt time");
      const payBy = new Date(current.haltedAt.getTime() + ADD_ON_GRACE_DAYS * DAY_MS);
      return now.getTime() < payBy.getTime() ? { state: "failed", payBy } : { state: "ended" };
    }
    case "cancelled":
      if (current.endKind === "pause") {
        const since = current.currentPeriodEnd ?? current.endedAt;
        if (since === null) throw new RangeError("A paused add-on has no pause date");
        return { state: "paused", since };
      }
      return { state: "ended" };
    default: {
      const unhandled: never = current.status;
      throw new Error(`Unhandled add-on status ${String(unhandled)}`);
    }
  }
}

export function addOnActions(view: AddOnView): readonly AddOnAction[] {
  switch (view.state) {
    case "none":
    case "ended":
      return ["buy"];
    case "active":
      return ["pause", "cancel"];
    case "ending":
    case "pausing":
      return ["keep"];
    case "paused":
      return ["resume"];
    case "failing":
      return [];
    case "failed":
      return ["pay-now"];
    default: {
      const unhandled: never = view;
      throw new Error(`Unhandled add-on view ${JSON.stringify(unhandled)}`);
    }
  }
}

export interface AddOnStatusChange {
  readonly status: AddOnSubscriptionStatus;
  readonly haltedAt?: Date;
  readonly endedAt?: Date;
}

/**
 * Our status after a Razorpay status event, or null for no change. Payments move a subscription to active through the
 * charged event, not here; cancelled is final.
 */
export function nextAddOnStatus(
  current: AddOnSubscriptionStatus,
  providerStatus: string,
  now: Date,
  startAt: Date | null,
): AddOnStatusChange | null {
  if (current === "cancelled") return null;
  switch (providerStatus) {
    case "authenticated":
      return current === "incomplete" && startAt !== null && startAt.getTime() > now.getTime() ? { status: "scheduled" } : null;
    case "pending":
      return { status: "past_due" };
    case "halted":
      return { status: "halted", haltedAt: now };
    case "cancelled":
    case "completed":
    case "expired":
      return { status: "cancelled", endedAt: now };
    default:
      return null;
  }
}
```

```ts
// add-on-activation.ts
import "server-only";
import { recordAddOnPayment, type AddOnPaymentRecord, type RecordedAddOnPayment, type ScopedTransaction } from "@firstfold/db";
import { issueTaxInvoiceSafely } from "./tax-invoicing";

/**
 * The one path for a captured add-on payment, however it arrived (the Razorpay webhook or the fake checkout): record it,
 * move the add-on to active for the period it paid, and invoice it, all in the caller's staff transaction. The invoice
 * is the last write. Idempotent on the provider payment id.
 */
export async function activateAddOnPayment(tx: ScopedTransaction, record: AddOnPaymentRecord): Promise<RecordedAddOnPayment> {
  const recorded = await recordAddOnPayment(tx, record);
  if (!recorded.alreadyRecorded) {
    await issueTaxInvoiceSafely(tx, recorded.payment, {
      kind: "add_on",
      addOnSubscriptionId: record.addOnSubscriptionId,
      periodStart: record.periodStart,
      periodEnd: record.periodEnd,
    });
  }
  return recorded;
}
```
