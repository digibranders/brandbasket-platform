# Taking a lapsed client's website offline

When a client's website has ended (the payment is due and unpaid, with no grace period), their website goes offline and comes back when they pay. The rule is `hasWebsiteService` in `packages/billing/src/access.ts`. Plan: `docs/plans/57-site-lapse-hosting-enforcement.md` in the workspace.

**The business's customers always see the site's own design.** While a site is offline they get the site's own maintenance page: a friendly line in the site's own typeface and look, with no word about why. They never see a Vercel or hosting error screen.

| Part | Where | What it does | Reacts in |
|---|---|---|---|
| The site | `templates/client-site` `proxy.ts` and `app/layout.tsx`, and each client site's own maintenance page | Answers every request with the site's own maintenance page, HTTP 503 with `Retry-After` and `noindex` | About a minute |
| The sync | Hourly job, `POST /api/internal/sync-site-hosting` | Records the lapse, tells the team in Teams, records the return when they pay. Touches Vercel only for a site that opted in | Within the hour; seconds after a client pays through the dashboard |

The site part only works for sites built from the template, and the maintenance page is the site's own: each client site designs its own (the template ships a plain one). A site that cannot show its own page can opt in to the host pause below, accepting that its visitors then see Vercel's page.

## Setting up a client

1. The site: copy `proxy.ts`, `lib/offline-check.ts`, `lib/maintenance-response.ts`, `lib/brandbasket.ts` and `components/` from `templates/client-site`, give `lib/maintenance-response.ts` the site's own design (the page is a plain HTML string, because Next refuses `react-dom/server` inside the proxy; any files it uses from `/public` must be let through in `proxy.ts`'s matcher), and set `BRANDBASKET_API_ORIGIN` and `BRANDBASKET_SITE_TOKEN` in the site's Vercel settings. Next 15 and older: name the file `middleware.ts` and the function `middleware`.
2. The console: open the client, Website tab, Vercel project. Paste the project id (Vercel project, Settings, General, Project ID: `prj_...`) and the team id (`team_...`) if the project is on a team. Save. The line under the form says Online, Offline since a date, or the last error.

A site is only recorded as offline if the business has a project that reached `live` and the row above exists. Sites without a row are never touched.

## Setting up the server (once)

1. `SITE_HOSTING_SYNC_TOKEN` is generated by `scripts/server/make-env-files.sh`; an existing server needs one added by hand (`openssl rand -hex 32`). `VERCEL_API_TOKEN` (a token for the Digibranders team) is needed only if some site opts in to the host pause.
2. `deploy/vps/install.sh backups` installs `brandbasket-site-hosting.service` and `.timer`. It does not enable the timer.
3. Read a dry run. It changes nothing:

   ```bash
   runuser -u brandbasket -- /usr/local/sbin/brandbasket-site-hosting-job --env-file /srv/brandbasket/shared/platform.env.local --dry-run
   ```

4. If the list is what you expect, `systemctl enable --now brandbasket-site-hosting.timer`.

## Pausing the host (opt-in, off by default)

Pausing a Vercel project is instant and reversible (an unpause restores the site in 4 to 9 seconds, no redeploy), but a paused project shows visitors Vercel's own page ("This Deployment is paused by the owner", 503, code `DEPLOYMENT_PAUSED`), in no one's design. So it is off by default. Turn it on only for a site that cannot show its own maintenance page:

```sql
update website_hosting set host_pause = true where business_id = '<business id>';
```

With it on, the sync also pauses the project when the site goes offline and unpauses it when the client pays, and a refused Vercel call fails the run (502).

## Who is told

When the sync takes a site offline, the Customers channel in Teams gets a "Website taken offline" card: the customer's name, mobile, email and website, the plan and its price, the plan's status, the date it was paid until, why it ended, when it went offline, the hosting project and what is done at the host, with a button that opens the client in the console. It is posted once, when the lapse is first found, not on later runs. If the Customers channel has no address set (console Settings), nothing is posted. Coming back online and a tripped brake do not post a card; a tripped brake (or a refused Vercel call for an opted-in site) fails the job, which emails the team through the existing failure alert.

## Reading a run

The job prints the report and exits non-zero (so the team gets the failure email) when a person needs to look.

| Answer | Meaning | What to do |
|---|---|---|
| 200 | Done. `items` lists each site that `went-offline` or came `back-online`; `held` lists sites left alone and why (`not-launched`, `payment-under-review`, `billing-unreadable`) | Nothing |
| 409 | The brake stopped a batch: more sites were due to go offline than one run allows (the larger of 3 or 5% of live sites, never more than 10). That many at once usually means a fault, not 11 clients all lapsing | Find the cause (billing outage, bad data). The sites' own proxies still show their maintenance pages once the platform says so |
| 502 | Vercel refused a change for a site that opted in to the host pause. The reason is on the site's row, shown in the console | Fix the project id or token, then wait for the next run or run the job by hand |

A site whose billing cannot be read is never changed in either direction. A payment waiting on staff (`payment-under-review`) is never taken offline for.

## Bringing a site back

The site comes back by itself within a minute of the platform saying the plan is paid (the proxy asks once a minute). A payment the client makes themselves, or Razorpay's renewal, is recorded within seconds; a payment recorded by staff in the console is picked up by the next hourly run, because the console cannot call this app. For a site with the host pause on, unpause the project on Vercel by hand if you need it back before then, after recording the payment.

## Known limits

- Pointing a business at a different Vercel project forgets that the old one was paused and leaves it as it was.
- The console cannot clear the project id once saved, and has no switch for the host pause (use the SQL above).
- `paused_at` and the `pausedAt` fields keep their names, but mean "when the site was found lapsed and taken offline".
