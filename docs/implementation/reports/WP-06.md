# WP-06: Database Role Check and Tenant Isolation Report

## 1. What Changed
- **Start-up Database Role Check**:
  - Implemented `assertCustomerAppRole` and `verifyStartupDatabaseRole` in `packages/db/src/scope.ts`.
  - Exported `assertCustomerAppRole`, `CUSTOMER_ROLE`, and `verifyStartupDatabaseRole` from `packages/db`.
  - Added production startup check in `apps/customer/src/instrumentation.ts`: when `NODE_ENV === "production"`, `register()` queries `current_user` from the pool via `assertCustomerAppRole(getAppDb())` and fails loudly if not `bb_app`.
- **Tenant Isolation Integration Tests**:
  - Added comprehensive cross-tenant read/write tests in `packages/db/src/cross-tenant-isolation.integration.test.ts` proving that queries scoped with `withTenantScope(businessA)` cannot read or modify data belonging to `businessB` across all major tables: `businesses`, `business_members`, `projects`, `enquiries`, `deliverables`, `change_requests`, `subscriptions`, `payments`, `charges`, `website_pages`, `team_calls`, `business_profiles`, `domains`, `patients`, `activity_events`, `report_documents`, and user-scoped `support_tickets`.
  - Verified that unscoped queries executing under `bb_app` return 0 rows for tenant tables due to row-level security policies.
