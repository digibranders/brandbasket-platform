# WP-17: Requests, Bell and Links Report

## 1. What Changed
- **Return to original link after sign-in**:
  - Replaced the invite-only `next` parameter handling with a safe same-origin allow list (`safeReturnPath`).
  - Implemented `safeReturnPath` in `apps/customer/src/lib/guard-rules.ts` to validate requested return paths. It validates path syntax, rejects external schemes (`http:`, `https:`, etc.), protocol-relative paths (`//`), backslashes (`\`), control characters, authentication paths (`/login`, `/signup`), API endpoints (`/api`), and unmapped top-level paths. For invite links, it validates the invite token format.
  - Added Next.js middleware in `apps/customer/src/middleware.ts` to forward request path and search params as `x-pathname` header so server-side route guards can determine the current request URL.
  - Updated `requireSignedIn` and `accessRedirect` in `apps/customer/src/lib/guards.ts` and `apps/customer/src/lib/guard-rules.ts` to pass the original URL via `returnTo` / `next` query parameter on redirect to `/login`.
  - Updated `apps/customer/src/features/entry/server/entry-access.ts` so already-authenticated visitors visiting `/login?next=...` are redirected to the safe return path.
  - Updated `apps/customer/src/features/entry/rules/account-entry.ts` `inviteReturn` helper to use `safeReturnPath`.
  - Updated customer login page `apps/customer/src/app/(auth)/login/page.tsx` to pass the `next` param to `signedInEntry`.

- **Canonical Request URL**:
  - Standardized request deep links to the canonical request detail page `/requests/${ticketId}`.
  - Updated `apps/admin/lib/server/request-notify.ts` to generate links targeting `${serverEnv().APP_ORIGIN}/requests/${ticketId}` instead of `/requests?ticket=${ticketId}`.
  - Updated `packages/shared/src/lib/account-panel.ts` so bell notifications link to `/requests/${ticketId}` directly.
  - Retained the sheet preview on `/requests` while establishing `/requests/[id]` as the canonical link destination.

- **Customer Acknowledgement Email for Change Requests**:
  - Created email template `requestAcknowledgementEmail` in `packages/email/src/templates/request-acknowledgement.ts` with typed inputs (`RequestAcknowledgementInput`). Includes customer name, business name, request title, reassurance of review time, canonical link button, and platform sign-off.
  - Exported template from `packages/email/src/index.ts`.
  - Implemented `sendRequestAcknowledgement` in `apps/customer/src/features/requests/server.ts` to send the acknowledgement email via transactional email transport (`sendTransactionalEmail`), checking `emailPreferenceAllows` for updates and skipping synthetic phone accounts (`isPhoneAccountEmail`).
  - Integrated acknowledgement dispatch in `apps/customer/src/features/requests/actions.ts` (`sendRequestAction`), ensuring the email is sent exactly once upon request creation (`if (created)`), alongside staff notifications.

Hello {customerName},

{requestUrl}

Warmly,
The BrandBasket Team
