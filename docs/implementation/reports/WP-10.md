# WP-10: Sign-up, Questions, and Unpaid State

## 1. What Changed
- **Service-Specific Sign-up Side Panel and Heading (a)**:
  - Created `apps/customer/src/features/entry/rules/signup-panel.ts` containing dynamic launch steps and copy mappings (`signUpPanelCopy`) based on selected basket services.
  - The side panel (`AuthArt`) and page heading on `/signup` now follow the chosen services. Website steps ("We build your website. You review it. It goes live.") appear only when Managed Website is in the basket.
  - Dedicated launch steps and promises provided for Managed Website, Social Media, Paid Ads, Social plus Ads bundle, and Team Invites.
- **Unpaid Customer Workspace Access (b)**:
  - Updated `apps/customer/src/lib/guard-rules.ts` with `UNPAID_ALLOWED_PATH_PREFIXES = ["/help", "/settings"]`, `isUnpaidAllowedPath`, and `unpaidHoldRedirect`.
  - Added Next.js middleware in `apps/customer/src/middleware.ts` to propagate `x-pathname` in headers for server components.
  - Updated `apps/customer/src/app/(app)/layout.tsx` to use `unpaidHoldRedirect`, allowing unpaid customers awaiting first payment to freely access Help (`/help`, `/help/contact`), Settings (`/settings/*`), and sign out without being redirected to `/checkout`.
  - Updated `apps/customer/src/app/(pay)/layout.tsx` to render header links for Help and Settings alongside the Sign Out button.
- **Abandoned Sign-up Reminder & Today Queue Owner (c, D21)**:
  - Added `signup_reminder_sent_at` timestamp column to `leads` table in `packages/db/src/schema/leads.ts`.
  - Generated and applied database migration `0226_signup_reminder_sent_at.sql` with chained metadata snapshot.
  - Added queries `listAbandonedSignupLeads` and `recordSignupReminderSent` in `packages/db/src/queries/leads.ts`.
  - Created email template `signupReminderEmail` in `packages/email/src/templates/signup-reminder.ts` with zero em or en dashes.
  - Created processor `processSignupReminders` in `apps/customer/src/features/entry/server/signup-reminder-job.ts` and internal API endpoint `POST /api/internal/send-signup-reminders` in `apps/customer/src/app/api/internal/send-signup-reminders/route.ts` authenticated via `SIGNUP_REMINDER_TOKEN`.
  - Implemented systemd timer `brandbasket-signup-reminder.timer` and service `brandbasket-signup-reminder.service` in `deploy/vps/systemd/`, along with runner script `scripts/server/run-signup-reminder-job.sh`.
  - Updated `todayQueue` in `apps/admin/lib/today-queue.ts` and `apps/admin/lib/server/today.ts` to query staff roster and attach the assigned staff owner's name to unpaid sign-up Today rows (`Signed up <date> · <owner>`), fulfilling decision D21.
- **Sign-up Code Step Survives Refresh (d)**:
  - Implemented `pending-signup-cookie.ts` in `apps/customer/src/features/entry/server/pending-signup-cookie.ts` using AES-256-GCM encryption with 10-minute expiry to securely preserve entered sign-up fields (name, email, business name, phone, etc.).
  - Updated `sendSignupCodeAction` in `apps/customer/src/features/entry/actions.ts` to set the cookie upon code dispatch.
  - Added `clearPendingSignupAction` in `actions.ts` and hooked it into the "Change email" button in `sign-up-form.tsx`.
  - Updated `/signup` page to inspect the cookie on initial render and restore the code verification step seamlessly after a browser refresh.
