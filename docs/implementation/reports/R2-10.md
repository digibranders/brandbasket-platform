# Work package report: R2-10 States and forms keep input

- Package: R2-10
- Branch: `r2/10-states-forms`
- Base: `origin/development` (rebased after #202 merged)

## 1. What changed

**Forms keep input.** A request that is dropped or rejected no longer throws the form to an error screen. It becomes the form's own failure, shows "Something went wrong on our side. Your answers are still here, press Save to try again.", and what was typed is put back into the fields after React resets the form (passwords, files and hidden fields are never put back). Redirects, not found and "action no longer on the server" (stale deploy) are not caught: they still reach Next and the existing reload notice.

- Shared: `packages/shared/src/lib/guard-action.ts` (`guardAction`, `isRecoverableDrop`, `restoreFormValues`, the message).
- Customer: `lib/use-guarded-action-state.ts` (drop-in for `useActionState`, returns a form ref as a 4th item), adopted in all 21 customer `useActionState` forms (entry, start, checkout, billing, blog create, enquiries, website, domain, restore, affiliate). `useActionForm` (settings, team, delete account, nominee) now catches drops too.
- Console: `lib/use-guarded-form-state.ts`, adopted in support (4 forms and new request, keeps the submission key so a retry cannot repeat the work), affiliate forms, referral code forms, affiliate login link, web address, Geography form.
- Unsaved changes: `lib/use-unsaved-changes-warning.ts` (tab close prompt plus a confirm before an in-app link is followed). Used by the blog post editor (replaces its own beforeunload effect), Business profile (through `SaveBarHost`, so every section form) and Brand kit (while an upload is in flight, since nothing is typed there).

**States.** Group-level boundaries so every route is covered, with closer ones kept:
- Customer: `(app)/loading.tsx`, `(pay)/loading.tsx`, `invite/[token]/error.tsx`.
- Console: `(protected)/loading.tsx` and `(protected)/error.tsx` (frame stays, rail still usable). `RouteError` now also reports to Sentry like the root boundary and shows the reload notice on a stale deploy.

### Already covered (not duplicated)
- Customer errors: `(app)`, `(auth)`, `(pay)`, affiliate portal, affiliate setup. Loading: Business, Settings, affiliate portal. Pages are driven by `Loaded<T>` panels with per-panel error and empty states; tables (invoices, enquiries, reports, requests) have empty states. Old top-level routes (plan, support, services, add-ons) only redirect.
- Console: 13 routes from R2-09 have their own loading and error; every list page has an empty state (checked by search; only `support/new` has none, it is a form).
- Viewer wording exists ("Ask your owner to do this.", viewer messages in actions).
