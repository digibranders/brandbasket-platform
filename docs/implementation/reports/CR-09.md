# CR-09: Inbox Enquiries and Reports to review

Branch `cr/09-enquiries-reports`, from `origin/development`. Plan sections S13 and S14, mock `mock-console-v2-inbox.html` (Enquiries, Reports, Report review).

## What changed

### Enquiries
`/leads` is a `DataTable` with a `FilterBar` (stages with counts, search, a source select echoed as a removable chip), a `BulkBar`, a `SidePanel` on `?open=` and the `n` shortcut (add an enquiry). Row: Business and contact, Source, Wants, Waiting (a Late chip and a Mono clock), the verb Open and a menu (Mark contacted, Mark lost).

- Status changes (Mark contacted, Mark lost, bulk Mark contacted) email nobody, so they run at once and show a toast with Undo. Undo restores the earlier status; a lead the system moved on in between counts as a failed undo.
- Send setup link (panel foot primary, and bulk) goes through a confirm that names the address ("Email the setup link to `<email>`?", bulk "Email the setup link to N people?"). A lead that already has a business gets View client instead, and bulk refuses a selection that includes one.
- No owner column, no Anyone, Mine or Nobody chips, no Assign form, no Owner fact. A stale `?owner=` in an address is ignored by the new page.
- `/leads/[leadId]` now redirects to `/leads?view=all&open=<id>`: the panel is the detail, and a full sheet on a phone. `/leads/new` loses the italic "Add a lead." heading: title "Add enquiry", back link "Enquiries", submit "Add enquiry" (D2, D22). It stays a page, not a dialog.
- States: skeleton rows while a filter changes and `loading.tsx` for the route, empty (existing wording), `error.tsx` (RouteError with Try again), panel error with Try again, success toasts.

### Reports to review
`/reports` is a `DataTable`: Client, Service, Month, State chip, Opening line, one verb per row. A draft or held report: Review (opens the review page). An approved report that was never sent: Retry send, behind a confirm that names the owner's address (or says nobody is emailed when there is no address). A send that fails shows an error toast with Retry, which asks the confirm again. The result words are the review page's own (`reportNotice`), so "The owner has been emailed." is never shown for owner-turned-off, no-address or already-sent.

The review page (`/reports/[reportId]`) keeps its form actions, but Send to customer now sits behind a `ConfirmDialog` naming the email, a report that was approved but never sent reads "Retry send", and a sent report whose email failed (`?done=sent.failed`) offers Retry send again (rerunning `sendReport` only retries the email). Hold and Release stay on this page as they were.

## Behaviour decisions to check

1. Mark contacted sets `call_done` (the same status the old "Mark talking" set) and is offered only for status `new`. A sign-up (`account_created`) cannot be changed by staff, so its row menu shows the reason.
2. The Late rule for enquiries is past 1 hour while the enquiry is still To contact (notes rule 4). The old `waitingOf` (late at a day) is unchanged and still tested; the new row model has its own rule. "Not paid" appears after 2 days on a sign-up that has not paid.
3. CD-15: the Reports list shows every unsent report whatever the date, so "while any draft is unsent" holds on this screen. The "1st to 5th" part is a Today rule: it is written as the tested pure function `reportReviewWindowOpen(now, unsentCount)` (India time) in `lib/reports-view.ts`, and is not wired to anything, because `lib/today-queue.ts` belongs to another package. The Today owner can import it.
4. The send from the list is a new action (`sendReportNowAction`) that returns words instead of redirecting; it does the same work as `sendReportAction` through `sendReportFromConsole`, logs the same access entry and activity. A bookkeeping failure after a successful send does not turn into "not sent".
5. A failed first send leaves the report `approved` (the PDF step runs after approval), so Approved, not sent is the failed-send row. No new data source.
6. Dead code now: `components/enquiries/enquiry-list.tsx` (still has the owner chips) is no longer rendered; it stays only because `enquiry-list.test.ts` must pass untouched. Delete both together in a follow-up, as was done for CR-08.

- "Signed up but not paid shows here once, after 2 days" in the empty state: a sign-up shows immediately today, and filtering it would be a behaviour change.
- Export selected: `/leads/export` takes a query, not ids. The header Export link stays.
- `InlineEdit` for status and notes: the existing edit form stays inside the panel.
- A filter bar, checkboxes and row menu on Reports: the mock has none and no bulk set exists for reports.
- `/leads/new` as a dialog (plan S13): kept as a page; same form.
