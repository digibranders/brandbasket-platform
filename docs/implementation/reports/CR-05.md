# CR-05: Clients directory and client workspace shell

Branch `cr/05-clients-workspace`, from `origin/development`. Plan sections S5, S6, 2.2. Not verified in a browser.

## What changed

### Clients directory (`/clients`)
- List view: `FilterBar` (stage pills with counts, search), `DataTable` at 44px rows with the Open verb, a Columns control for Monthly and Paid through, a services column (one chip per service, name plus state word), a red dot with a spoken "Late", and a `SidePanel` quick view on `?open=`. Filters and search stay in the address, so the server filters.
- States: empty ("No clients yet."), no match (with Clear filters), loading (`clients/loading.tsx` plus the table's own loading state), error (`clients/error.tsx`, Try again).
- Builds view at `?view=builds`: the old `/projects` board (same data, same columns, same Needs action, Late, On hold, All scope). The Builder filter is gone (no assignee). The List and Board toggle of `/projects` is gone; the board is the only Builds layout. Access log keeps `projects.list` for this view and `clients.list` for the list.
- No owner, Mine or assignee. "Owner" under a business name is the customer's owner.

### Workspace shell
- Six tabs: Overview, Website, Services (`/services`), Money (`/billing`), Requests (`/requests`), Account (`/people`). Header gets the client id in Mono.
- Overview: exceptions strip, a Next step card that covers every service, a Services block, the customer mirror, history, and the side facts. "Nothing is waiting on us." shows only when every read worked and there is no exception. A failed read shows "We could not check what is waiting" with Try again; the history, mirror and intake panels each fail on their own. Exception order follows ruling 11 (failed renewal first), then the mock order: kickoff not confirmed, first preview late, preview silent 5 days (ruling 15), address check failing, domain move, flagged payment, lapse, closing, privacy request.
- Package and Ad credit rows are left out of the Overview money facts (`BillingFacts` takes `packageFacts: null`). The Money tab still passes them (its body is CR-07's).
- Services tab: a real page now. Until CR-07 moves the forms it lists the client's services with state and a link to where each is run today (Website tab, Money tab `#numbers`, `#add-ons`). An old `/services?<notice>` link still forwards to the tab that shows the notice.

### New and changed files
New: `lib/client-exceptions.ts`, `lib/client-services.ts`, `lib/clients-view.ts`, `lib/server/client-overview.ts`, `components/console/client-overview-cards.tsx`, `components/console/try-again.tsx`, `components/clients/clients-directory.tsx`, `app/(protected)/clients/builds-view.tsx`, `clients/loading.tsx`, `clients/error.tsx`, `clients/[businessId]/loading.tsx`, plus tests.
Changed: `lib/client-tabs.ts`, `lib/client-next-step.ts` (additive: `overviewCard`), `clients/page.tsx`, `clients/[businessId]/{layout,page,parts}.tsx`, `services/page.tsx`, `website/page.tsx` (one notice word, "Plan and billing" to "Money").
No server action, query, billing or access rule changed. No migration. No new database query (the reads reuse `listLiveServiceLines`, `listAddOnsToContact`, `listPaymentsNeedingAttention` with a business id, `findOpenClosureForBusiness`, `listOpenPrivacyRequests`).

## Open questions

1. Kickoff exception and card link to the Website tab. The mock opens the kickoff prompt dialog from the Overview; that shared prompt is CR-03's component, so the card opens the Website tab for now.
2. Privacy request match: a request names a person, not a business, so it counts for this client when its `subjectUserId` is the owner's user id. Requests filed by a visitor without an account will not appear on the strip.
3. Address failing exception uses the stored domain status (`misconfigured` or `degraded`). The detailed DNS result only exists after a manual check, so the strip does not quote it.
4. Preview silent threshold is a constant (`PREVIEW_SILENT_DAYS = 5`) in `lib/client-exceptions.ts`. CR-03 may define its own for Today; unify when both are merged.
5. Board cards still show "No builder" or a builder name (`lib/project-board.ts`, tests untouched). With one staff account this reads as an assignee; change it with the Builds board tests when you say so.
6. Tab counts and the Money "!" mark from the mock are not built (no data source wired for Requests count; Money mark needs a decision on where it reads from).
7. The Services tab is an interim list. Its forms still live on the Money tab with their existing redirects (`/billing?numbers=...`), which CR-07 moves.
8. A second pass is needed once CR-03 merges: it also links to `/clients/[id]` pages and may want the exceptions function for Today rows.
