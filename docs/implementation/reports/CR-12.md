## What changed

- Health: six rows (Emails, Webhooks, App errors, Google connections, Teams alerts, Scheduled jobs) each with Fine, Needs a look or Not known, and an Open link. A read that fails shows "Could not check" and never "Fine". Scheduled jobs always say "Not known" because no timer writes a run record (CD-20).
- Emails and webhooks: "Resend all failed" in the header, and every Resend (list, email detail, alert detail), now asks first through `ConfirmDialog`. The existing actions are unchanged. No row selection bar: the only bulk set is the existing "resend all failed", which already has its header button, so a BulkBar with nothing to select would be unrequested UI.
- App errors: status buttons on the detail page; a change shows a toast with Undo (10 seconds) and emails nobody. New action `setErrorStatusAction` wraps the existing `updateErrorIssueStatus` with the same occurrence count guard. The old inline form (status select, assignee select) is removed. The assignee is left as it was on every status change.
- Settings: Teams "Remove" now asks first. The dialog sits beside the save form, not inside it, to avoid a form inside a form.
- Access: no role picker, no role or Can column, no change role control. Table shows person, status, last signed in, and Switch off (behind the existing confirm) or Switch on. The invite is for the recovery administrator only and posts a fixed `admin` role to the unchanged action. Sign-in protection stays read-only.
- Utility pages: wording from the mock. 404 button is now "Back to Today" (was "Back to the journey").
- `/design-system`: `requireStaffAccess()` added after the production 404.
