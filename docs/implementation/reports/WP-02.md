## Summary of Changes

1. **Prevent Personal Business Creation on Invite Sign-up:**
   - Modified `apps/customer/src/features/entry/server/listing-account.ts`:
     - Extended `createListingAccount` with optional `options?: ListingAccountOptions` containing `inviteToken`.
     - When `options?.inviteToken` is provided and resolves to a valid invite for the signing-up email (checked via `checkBusinessInvite(getStaffDb(), ...)`), skips `createUnlistedAccountBusiness` and `recordLeadForSignup`. The invitee account is created cleanly without a personal business.
   - Modified `apps/customer/src/features/entry/actions.ts`:
     - Updated `signUpAction` to parse `inviteToken` from `formData.get(NEXT_FIELD)` and pass it to `createListingAccount`.

2. **Active Business Selection and Persistence:**
   - Modified `packages/shared/src/lib/access.ts`:
     - Exported `ACTIVE_BUSINESS_COOKIE = "bb_active_business"`.
     - Updated `decideCustomerAccess(user, memberships, activeBusinessId?)` so that when `activeBusinessId` matches one of the user's active memberships, that workspace is selected. When absent or naming an unrecognized business, falls back to the earliest membership.
   - Modified `apps/customer/src/features/team/actions.ts`:
     - Updated `acceptInviteAction` so that upon successful acceptance of a business invite, it sets `ACTIVE_BUSINESS_COOKIE` to the invited `businessId` on `cookies()` with `{ path: "/" }`.
   - Modified loaders to read and respect `ACTIVE_BUSINESS_COOKIE`:
     - `apps/customer/src/lib/guards.ts` (`getCustomerAccess`)
     - `apps/customer/src/features/entry/server/entry-access.ts`
     - `apps/customer/src/platform/lib/server/customer-tenant.ts`

3. **Pre-acceptance Invitation Validation & Plain-Words Refusal Messages:**
   - Modified `packages/db/src/queries/business-invites.ts` & `packages/db/src/index.ts`:
     - Added `findBusinessInviteByToken`, `evaluateBusinessInvite`, and `checkBusinessInvite` to evaluate invite validity (not found, revoked, used, expired, wrong email) on the staff connection without mutating database state.
   - Modified `apps/customer/src/features/team/loader.ts`:
     - Exported `loadInviteForToken(token, userEmail?, now?)`.
   - Modified `apps/customer/src/features/team/rules.ts`:
     - Exported `refusalTitle(reason: BusinessInviteRefusal)`.
     - Standardized plain-words copy without em dashes or en dashes for all refusal states.
   - Modified `apps/customer/src/app/invite/[token]/page.tsx`:
     - The page checks the token with `loadInviteForToken` before rendering the Join button.
     - Expired, used, withdrawn, and wrong-address invites are refused upfront with plain-words explanation. The Join button is hidden when refused.

2. **Already used invitation:**
   - **Title:** `This invitation has already been used.`
   - **Explanation:** `This invitation has already been used. Ask the owner to send a new one.`

3. **Wrong email address invitation:**
   - **Title:** `This invitation is for a different email address.`
   - **Explanation:** `This invitation was sent to a different email address. Sign in with that address to accept it.`

4. **Additional refusal states aligned to pattern:**
   - **Withdrawn invitation:**
     - **Title:** `This invitation was withdrawn.`
     - **Explanation:** `The owner withdrew this invitation. Ask them to send a new one.`
   - **Invalid link / token not found:**
     - **Title:** `This invitation link is not valid.`
     - **Explanation:** `This invitation link is not valid. Ask the owner to send a new one.`
