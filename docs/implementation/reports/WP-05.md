# WP-05: Account Erasure Ordering Report

## 1. What Changed
- **Erasure Ordering Fix**:
  - Re-ordered the steps in `apps/customer/src/platform/lib/account-erasure-run.ts` so that `eraseRows` executes inside a transaction under lock *before* `eraseWebsiteContent` (CMS deletion) is attempted.
  - If an account is restored during the 30-day window, `eraseRows` detects the restored state under row lock, safely skips the erasure, and ensures website content and database rows are preserved intact.
  - Updated `docs/account-erasure.md` documentation to accurately reflect the corrected ordering.

- **Route Tests & Integration Coverage**:
  - Added comprehensive route tests in `apps/customer/src/app/api/internal/erase-closed-accounts/route.test.ts` verifying HTTP 503 when the erase token is unset, HTTP 401 on missing or invalid Bearer tokens, HTTP 400 on malformed queries, and proper dispatching to `runAccountErasure`.
  - Added full integration tests in `apps/customer/src/platform/lib/account-erasure.integration.test.ts` testing race condition where an account is restored immediately prior to lock execution, dry-run mode, limit enforcement, and endpoint invocations.
