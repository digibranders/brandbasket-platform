# CR-08: Inbox Requests as one list

Branch `cr/08-inbox-requests`, from `origin/development`. Plan section S12 and S10, mock `mock-console-v2-inbox.html` (Requests).

## What changed

Support tickets and change requests are one list. A change request is a ticket with a `change_requests` row, so the list is the ticket list, and a type chip (Support or Change) plus a state chip says which and where it is. The side panel carries the conversation (oldest first), the reply box, and for a change request its moves. `/support` and a client's Requests tab render the same component, `RequestsWorkspace`.

### Behaviour

- Queues: Needs reply, Waiting on customer, Done (counts from `countSupportQueues`); a client's tab adds All (no counts: there is no per-client count source).
- Type chip Support or Change; change chips: Needs a quote, Quote not paid, Paid, in progress, In progress, Sent for checking, Fix asked, Approved, Done, Declined, Quote turned down. Late (red) from 24 hours, Past 4 hours between 4 and 24. Clocks in Mono, "1d 03h".
- Thread oldest first; staff messages read "You". The banner is computed from the messages, so after a reply it reads "Waiting on the customer" (walkthrough D10). The old "customer sees: Sent" jargon is gone from this screen.
- No owner, Mine, Nobody or assignee chip or column anywhere on the screen or in the details editor (D1).
- Close and Reopen are status only and email nobody: no dialog, a toast with Undo. A public reply and every change request move email the customer: each goes through a dialog that names the email, with no undo.
- "Reopen and reply" in one step for a closed request (see the Closed note below).
- States: loading (skeleton rows while a filter changes, `loading.tsx` for the route, panel skeleton while a request loads), empty (R2-12 wording; client tab "No requests from this client."), error (`error.tsx`; panel error with Try again), success (toasts).

## Decisions to check

1. Close sets the status to Resolved, not Closed. The database lets staff move Resolved back but never move Closed, so Undo and Reopen only work from Resolved. Both count as Done in the queues. Requests that are already Closed (set in the old Ticket details form or by the customer) cannot be reopened or replied to publicly, as before; the panel says so and offers the internal note. Allowing Closed to reopen needs a rule change in `updateSupportTicketByStaff` and `canTransitionSupportStatus`, which this package must not do.
2. Reopen sets the status to Triaged. Undo of a close restores the old status where the rules allow it, otherwise Triaged (a Resolved ticket cannot go back to New or Waiting on you).
3. Change request moves still use the existing form actions, which redirect to the client's Requests tab with the outcome line (`?requests=` and `?mail=`). Acting from the Inbox panel therefore lands on that tab. Making them stay on the list needs a change to `request-actions.ts`.
4. Shortcut `c` is not registered: ruling 7 says `e` runs the row verb everywhere and there is no `c`. `r` (focus the reply) and `n` (new request) are registered, `Enter` and `j` `k` come from DataTable and SidePanel.
5. An internal note has no Undo (no action deletes a note). The mock shows one; no data source, no element.
6. The mock's "Sent by email" tag on staff messages is left out: nothing records that the email went.
7. `ToastRegion` is mounted by this screen because the layout does not mount it yet. If CR-01's owner mounts it in the shell, remove it from `requests-workspace.tsx` and `request-page-view.tsx`.
8. `support/new` is unchanged (the mock's New request dialog is the same form; the header link and `n` open the page, a client's tab opens it with the client preselected).
9. Dead code now: `components/console/requests-section.tsx` and `request-banner.tsx` (and their tests) are no longer rendered. They are left because their tests must pass untouched; delete them together in a follow-up.
10. The type filter and a per-queue count for a client are not built (no data source).
