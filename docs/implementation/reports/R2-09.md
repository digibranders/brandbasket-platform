# Work Package Report: R2-09 Console Money, Compliance and System

## 1. What changed

Re-theme of the staff console's Money, Compliance and System screens to the premium language, with no behaviour change to any server action.

- **Token bridge.** The shared patterns use Release 2 token names (`pos-*`, `neg-*`, `canvas`, `border`, `surface-hover`, `accent-wash`, `shadow-dialog`, `type-title`, `motion-pulse`) that only the customer app defined, so shared patterns rendered partly unstyled in the console. `packages/shared/src/styles/theme.css` (imported only by the console) now defines them with the same values.
- **StatTile** gained a `note` line, `size="medium"` for long money figures and `warning` and `negative` tones. Backwards compatible.
- **StatTiles** (console): the screen's figures as shared StatTiles on one resting card. Replaces `Figures` on Payments, Invoices, Emails and webhooks, Leaving, Coupons, Coupon detail, Privacy requests and Breaches.
- **Refund dialog** (payment rows on the client's Plan and billing tab, where Payments lists each payment): the shared console `ConfirmDialog` with full or part of it, amount, reason, the consequence, the credit note line and a preview of the customer's email. Secondary "Record a refund made outside BrandBasket" is its own dialog with its tick box. The refund action, the manual action and their validation are untouched. The dialog sends `confirm=yes`, which `parseRefundForm` already requires.
- **Destructive confirms use ConfirmDialog:** refund, manual refund, close a privacy request, close a breach, switch off a staff member, delete a coupon code (the form no longer nests a form).
- **Payments:** Needs a look section (first 5 flagged payments, shown on the All filter), figures as StatTiles, the table as the one focal card (3px gold top edge), shared EmptyState.
- **Compliance:** privacy requests show the 30 day clock as "17d 08h remaining" in Mono, red only when overdue; breaches show 6 and 72 hour clocks as "5h 12m left". Both pages have figure tiles and use tokens instead of legacy `ink-soft` and `accent-pale` classes.
- **Staff:** new read-only "Sign-in protection" section reports the Cloudflare Access state of the current request (`REQUIRE_CF_ACCESS` and the verified header). Changes nothing; the proxy still enforces it.
- **States:** `loading.tsx` (warm skeleton) and `error.tsx` (shared ErrorState with Try again) for payments, invoices, pricing, coupons, affiliates, privacy-requests, breaches, access-log, staff, support/errors, deliveries, settings and leaving. Shared EmptyState for empty lists on the pages above. Success states are the existing Notice lines.
- **Forms and dialog:** `field-styles.ts` now gives 42px controls, 8px radius, ink focus ring, for every console form. `ConfirmDialog` takes the dialog spec (20px radius, 28px padding, 22px title, dialog shadow).
- Cleanup: `font-serif` in Leaving figures became `font-figure`; `text-ink-soft` became `text-ink-2` on the touched pages.

Not touched: console shell, Today, client workspace, Calls, customer app, packages/db, billing.

## 6. Open questions

1. **Mock refund consequence is not true of the code.** The mock says a refund cancels the subscription and revokes hosting. `executePaymentRefund` only refunds, issues the credit note, cancels owed affiliate earnings and emails. I wrote the true line and added "The plan and the website are not changed". If the owner wants a refund to cancel the plan, that is a behaviour change for a separate package.
2. **Payment detail page.** There is no standalone payment detail route; each payment is a row with an anchor on the client's Plan and billing tab (the Payments page links to it). The refund dialog lives there. A separate detail route was not built (no unrequested UI).
3. **Settings "Remove" Teams address** still submits without a dialog: it is a button inside the address form, so wrapping it needs the form split. Say if you want it.
4. **Roles.** Staff page still shows the role picker and invite form (Release 1 behaviour). The brief says one staff account; removing roles is a behaviour change, so I left it.
5. **Prices and Affiliates screens** were re-themed only through shared classes, tokens and states (no mock). Their layouts are unchanged.
6. The mock's "Paytm", webhook latency tiles, "Gateway health" and "Active refunds" tiles have no data source here, so they were not built.
7. R2-10 also owns `loading.tsx` and `error.tsx`. I added them for my 13 routes only; expect a trivial merge if R2-10 touches the same files.
