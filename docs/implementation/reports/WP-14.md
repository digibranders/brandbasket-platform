# WP-14: Kickoff "Call Completed" Prompt and Notification Report

## 1. What Changed
- **Renamed "Held" to "Call Completed"**:
  - Replaced all staff-facing and internal uses of "call held" with "Call completed" across the staff console and customer portal.
- **Console Prompt Popup & Notifications**:
  - Implemented accessible local `KickoffPromptPopup` component (`apps/admin/components/console/kickoff-prompt-popup.tsx`) without extra UI libraries, following light theme and existing tokens.
  - When a booked kickoff call time passes, prompts staff with: "Did the kickoff call with {businessName} happen?" offering three explicit actions:
    1. `Call completed` (with optional notes)
    2. `They did not join`
    3. `Reschedule`
  - Integrated prompt on Today queue and console shell notification area (`kickoff-prompt.tsx`).
  - Read-only call status presented on client Website and Messages tabs; action execution is centralized exclusively in the prompt.
- **24-Hour Automatic Fallback (D31)**:
  - If staff do not respond to the prompt within 24 hours of scheduled call completion, the build starts automatically via `markProjectReadyAfterKickoff` with `startedWithoutCallConfirmation: true`.
  - Added schema column `started_without_call_confirmation` to `projects` via migration `0226_started_without_call_confirmation.sql`.
  - Today list displays the fallback status clearly: "Started without call confirmation".
- **Customer Kickoff Status Messages**:
  - Before call: "Your kickoff call is booked for {time}"
  - After call time, before confirmation: "We will start your website right after your call"
  - After Call completed: "Thanks for the call. We are getting your website started"
