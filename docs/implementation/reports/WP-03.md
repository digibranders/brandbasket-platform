# WP-03 Staff account protection: Implementation Report

## Summary of Changes

WP-03 protects the single staff account and guards destructive operations in the staff console (`apps/admin`).

1. **Cloudflare Access JWT Verification (`apps/admin/lib/server/cloudflare-access.ts`, `apps/admin/proxy.ts`):**
   - Implemented optional Cloudflare Access verification triggered when `REQUIRE_CF_ACCESS=1` (or `true`).
   - Verifies the `Cf-Access-Jwt-Assertion` header on incoming requests.
   - Retrieves and caches the team public JWKS from `<CF_ACCESS_ISSUER>/cdn-cgi/access/certs` using `jose.createRemoteJWKSet`.
   - Validates JWT signature, issuer (`CF_ACCESS_ISSUER`), audience (`CF_ACCESS_AUDIENCE`), and expiration.
   - When the flag is disabled (`REQUIRE_CF_ACCESS=0`), requests pass through unimpeded without requiring the header.
   - Refuses unauthenticated or invalid requests with HTTP 401 Unauthorized (`Authentication required via Cloudflare Access`).
   - Wired into Next.js 16 proxy middleware (`apps/admin/proxy.ts`), protecting console routes while exempting public assets and static files (`/_next/`, `/icon.png`, `/apple-icon.png`, `/api/health`).
   - Documented setup and operational runbooks in `docs/STAFF-ACCESS.md`.
   - Updated `apps/admin/lib/server/env.ts`, `apps/admin/.env.example`, and `apps/admin/.env.production.example`.

2. **Destructive Action Confirmations and Accessible `ConfirmDialog` Component:**
   - Built `apps/admin/components/console/confirm-dialog.tsx`:
     - Accessible modal dialog using the native HTML `<dialog>` element (`showModal()` / `close()`).
     - Focus trapping and keyboard dismissal (`Escape` key, backdrop click).
     - Styled with existing design tokens (`bg-surface`, `border-line`, `text-ink`, `text-ink-2`, `buttonSecondary`, `buttonDanger`, `buttonPrimary`).
     - Renders title, consequence line, cancel button, and confirm button.
     - Automatically injects `<input type="hidden" name="confirm" value="yes" />` upon form submission.
   - Refactored all destructive actions to require explicit `confirm === "yes"` verification:
     - **Cancel build** (`cancelProjectAction`): refuses and redirects to notice `unconfirmed` unless confirmed. Integrated into `ProjectControls` with `ConfirmDialog`.
     - **Add free round** (`grantRoundAction`): refuses and redirects to notice `unconfirmed` unless confirmed. Integrated into `ProjectControls` with `ConfirmDialog`.
     - **Change domain** (`switchDomainAction` and `changeFreeAddressAction`): refuses and redirects to notice `unconfirmed` unless confirmed. Integrated into `MoveDomainPanel` and `ChangeFreeAddressForm` with `ConfirmDialog`.
     - **Mark refunded** (`markPaymentRefundedAction`): refuses and redirects to notice `unconfirmed` unless confirmed. Integrated into `ClientPayments` with `ConfirmDialog`.
     - **Restore account** (`restoreClosureAction`): refuses and redirects to notice `unconfirmed` unless confirmed. Integrated into `ClientPeoplePage` with `ConfirmDialog`.
     - **Close account** (`closeAccountAction`): added admin action requiring confirmation, scheduling account closure in 30 days. Integrated into `ClientPeoplePage` with `ConfirmDialog`.
   - Updated notice registries in `packages/shared/src/lib/project-launch-notices.ts`, `packages/shared/src/lib/domain-connect-notices.ts`, and `apps/admin/lib/people-notices.ts`.

3. **Role Architecture Preserved:**
   - Existing single account role architecture preserved; single account functions with full admin oversight capabilities.
